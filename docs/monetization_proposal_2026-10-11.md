### 1.2 プラン・価格・無料トライアル

| 商品 | RevenueCat package | 価格（日本） | トライアル（RevenueCat API の product 定義） |
|---|---|---|---|

| developerSupport | `developerSupport` | ¥500 | なし（ペイウォールからは導線なし） |

- ペイウォールは**年額が初期選択**。年額を選んでいるときはトライアルの表記が無く、「年額プランを始める ¥9,000/年」となる。月額を選ぶと「7日間無料で試す」に変わる。

### 1.4 レビュー依頼の発火条件

- `VoiceAppFeature` の `recordingCompleted` で、**録音完了の累計回数が2回以上なら毎回** `SKStoreReviewController.requestReview` を呼ぶ（2秒遅延）。実際の表示は Apple の上限（年3回）に任せている。
- 満足の瞬間（例: 文字起こし成功後）に絞る設計ではない。今回の提案範囲外だが、★4.20 を上げる余地として残しておく。

## 3. 改善案（効果が大きい順）

### 提案1: 月1回の課金案内（最優先・entaku 方針）

**現状:** 自動の課金案内は「10回目録音時に1回きり」だけ。有料機能に触れないユーザーはペイウォールを一度も見ない（月アクティブ1,172人のうち、ペイウォールを見たのは167人）。

**仕様（推奨の初期値）:**
- 対象: 非課金ユーザーのみ。
- 間隔: 前回の自動案内から **30日以上** 経過していること。10回目録音時のトライアル訴求も「自動案内」に数え、続けて出さない。
- インストール直後: インストール日から **3日間** は出さない（`installDate` が未記録なら出さない）。
- 表示タイミング（どちらか先に来たほう）:
  - (a) **録音を保存し終えた直後**（`recordingCompleted`）。ただし、同じタイミングで初回録音のお祝いモーダルや10回目トライアル訴求が出る場合は出さない。出した回はレビュー依頼を出さない（ダイアログを重ねない）。
  - (b) **アプリ起動時**（`VoiceAppFeature.onAppear`）。ただし、初回起動（チュートリアル）時と、起動時の App Open 広告が出る起動回（起動3回に1回）は出さない。
- 録音中・一時停止中・エンコード中・再生中は出さない。
- 画面: 既存の `PaywallView` を fullScreenCover で出す。右上の閉じるボタンはすぐ押せる（遅延表示なし）。
- 計測:
  - `monthly_paywall_shown`（`trigger` = `launch` / `after_recording`）
  - `paywall_viewed` / `paywall_purchase_completed` に `source`（`monthly_launch` / `monthly_after_recording` / `feature_gate` など）を付ける。これで「月1案内経由の購入」を数えられる。

**見込み効果:** 対象は非課金アクティブ約1,000人。月1回見せると、ペイウォール閲覧は月167人 → 約700〜900人に増える。自発的に開いた人ほど購買意欲が高くないので、閲覧→購入率を現状1.8%の1/3〜1/2（0.6〜0.9%）と置くと、トライアル開始 +4〜8件/月。トライアル転換25%として新規有料 +1〜2件/月、MRR は3か月で +$7〜20 程度。

**工数:** 0.5〜1日（実装＋テスト）。

**リスク:** 煩わしさによるレビュー低下（★4.20）と解約。月1回・閉じる即可・録音中は出さない、で抑える。

**検証方法:** リリースから28日間で、次を判定する。
1. `monthly_paywall_shown` のユーザー数、および `source=monthly_*` の `paywall_purchase_completed` 件数
2. RevenueCat の New Trials（月5件の基準より増えたか）
3. 副作用として、App Store の評価平均と新着の低評価レビューに「広告／課金がうざい」系が増えていないか

判定: トライアル開始が月8件以上、かつ★の28日平均が4.1以上を維持していれば継続。そうでなければ間隔を60日に延ばす。

**要判断（推奨値で実装を進める）:** 間隔30日、インストール後3日、起動時と録音後の両方を使うこと。

### 提案2: 計測の修正（キャンセル誤判定・表示元・プラン名）

- `PurchaseManager` でキャンセルエラー（`ErrorCode.purchaseCancelledError` / `userCancelled`）を包み直さずにそのまま投げる。そうすればキャンセル時に「購入に失敗しました」アラートが出なくなり、`paywall_purchase_cancelled` が正しく記録される。
- `PaywallView` に `source` 引数を足し、全イベントに付ける。`product_name` には年額／月額を入れる。
- リストアに失敗したときの文言を「復元できる購入が見つかりませんでした」に変える。
- **効果:** 誤アラートで購入を諦めていた人の一部を取り戻せる（試行10人中8人が「失敗」扱い。多くは実際にはキャンセル）。施策の効果判定もできるようになる。
- **工数:** 0.5日。**リスク:** 低。
- **検証:** 2週間後、`paywall_purchase_cancelled` が計上され、`failed` が試行の2割未満になっていること。

### 提案3: AI議事録ロック画面に購入ボタンを付ける

- 議事録タブを開いた非課金ユーザーは、すでに文字起こしを終え、要約を欲しがっている状態にある。購買意欲が最も高い瞬間なのに、購入ボタンが無いので取りこぼしている。
- 「7日間無料で試す」ボタンを付け、ペイウォールを（`source=minutes_lock` で）開く。サンプルの要約結果をぼかして見せると、なお良い。
- **効果:** 月+1〜2トライアル（推定）。**工数:** 0.5日。**リスク:** 低。
- **検証:** 28日間で `source=minutes_lock` の viewed→trial を見る。

### 提案4: 年額にも7日間無料トライアル／訴求と着地を揃える（要判断）

- 2026年に年額の直接購入は0件。初期選択の年額にはトライアルが無いのに、入口の文言は「7日間無料」を押し出しているため、ずれている。
- 案A（推奨）: ASC で年額にも7日間無料を設定し、ペイウォールの年額選択時に「7日間無料 → その後¥9,000/年（月あたり¥750）」と表示する。
- 案B: 初期選択を月額に戻す（トライアル文言と一致させる）。
- **効果:** 年額比率が上がると、年額はLTVで月額の約9か月分。月次解約20%の現状では月額の平均継続は約5か月なので、年額1件は月額約2件分の価値がある。
- **工数:** ASC 設定＋0.5日。**リスク:** トライアル後の年額請求による返金要求が増える。
- **検証:** 8週間で、年額のトライアル開始・転換数と返金数を見る。
- **要判断:** 年額トライアルを入れるか（推奨A）。

**結果（2026-10-11、entaku 承認 → issue #232）**
- **ASC の設定:** 変更していない。年額（`annual`、subscription 6781730502）には、ASC で**すでに**7日間無料が設定されていた（読み取りで確認）。
  - 年額: `FREE_TRIAL` / `ONE_WEEK`、開始日 2026-06-18、終了日なし、175テリトリー。販売テリトリーも175、全テリトリー数も175で、全域をカバーしている。
  - 月額（`pro`）も同じ内容。
  - RevenueCat の product 定義で年額の `trial_duration` が null だったのは、RevenueCat 側のメタデータが古いだけ。実際のトライアルは ASC/StoreKit で有効になっている。
- **本当の原因は課金画面の表示だった。** 初期選択の年額にはトライアルの表記が無く、月額だけに「7日間無料」を固定の文言で出していた。そのため、年額が無料で試せることがユーザーに伝わっていなかった。
- **アプリ側の対応（`51da5ee4` / `1d7e52f2` / `a4415763`）:**
  - トライアルの有無と日数を、StoreKit の introductory offer と RevenueCat の適格判定から決める。対象外・判定できない人には表記を出さない。
  - 年額・月額の両方で「7日間無料 → その後 ¥9,000/ 年」と CTA「7日間無料で試す」を表示する。文言は45言語で追加した。
  - 購入イベントの `product_name` を、選んだプラン（annual/pro）にし、`has_trial` を追加した。
- **残課題:** 課金画面の外の入口は、まだ「7日間無料」を固定の文言で表示している（設定画面のバナー、10回目録音時のトライアル訴求、AI議事録のロック画面のボタン）。トライアルの対象外の人にもそのまま見える。

### 提案5: 月額の値上げテスト（要判断）

- 競合の月額は¥2,200〜2,500、当アプリは¥1,000。RevenueCat Experiments で ¥1,000 と ¥1,500 の offering を50/50で出す。
- **効果:** 転換率が3割落ちても売上は横ばい以上の見込み。**工数:** 1日（商品追加＋審査）。
- **リスク:** 母数が少なすぎる（トライアル月5件）ため、統計的に判定するには数か月かかる。**提案1で母数を増やしてから実施するのが推奨。**
- **検証:** 8週間で、ユーザーあたり売上（Experiments の Realized LTV per customer）を比較する。
- **要判断:** 値上げするか。推奨は「提案1・2の効果が出た後（2026-12以降）に実施」。

### 採らなかった案

- **無料範囲を削る（録音時間制限など）:** 上位の競合はいずれも録音を無料にしている。★低下と離脱のリスクが大きいので推奨しない。
- **文字起こし無料枠（累計3回）の変更:** Notta 型の「冒頭N分だけ見せる」は有望。ただしサーバー側コストと仕様の分岐が大きいので、別途検討とする。

### 提案1 の実装メモ（issue #228、branch `feature/monthly-paywall`）

- 判定ロジック: `ios/VoiLog/Store/MonthlyPaywallPolicy.swift`（純粋関数）。組み込み先: `VoiceAppFeature`（`onAppear` と `recordingCompleted`）。
- 猶予期間の起点は既存の `InstallDate` ではなく、新しいキー `monthly_paywall_first_seen_at` にした。`InstallDate` は**通知を許可した人にしか記録されない**ため（`VoiceMemoApp.swift` の通知許可コールバック内で記録している）。既存ユーザーは、このバージョンで初めて開いた日から3日後が対象になる。
- 起動時の ATT 許諾ダイアログは、未決定のユーザーにだけ出る。ペイウォールと同時に出ることがあるが、システムのアラートが上に重なるだけで操作は止まらない。
- 起動時判定は**コールドスタートの初回表示時だけ**（バックグラウンドからの復帰では出さない）。
